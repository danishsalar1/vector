Evidence UUID and timestamp are generated by desktop normalization, not emitted
by the handset. Timestamp is normalization time, not sensor acquisition time.
Elapsed time is from the report. Scan ID, attempt ID, nonce, sequence, full binding,
and collection_not_before are NOT retained in EvidenceRecord. The diagnostic
ValidatedProbeResponse also has no owner envelope fields (v1 attributed observations
do, but v2 diagnostics are a separate field). Neither mutable EvidenceRecord nor
DiagnosticResult is an authentication receipt. Reconstructing current context for
an arbitrary record would fabricate an association.

Phase 8D policy explicitly does not authenticate records, resolve their IDs, or
establish session freshness. Its provenance authority, issuer, and binding types
are descriptive domain classifications, not permission to infer OEM provenance.
No diagnostic metric supplies an admissible OEM-origin/history signal.

Boundary implementation: direct invocation of the existing lifecycle consumes its
returned canonical result without a caller observation override. It checks the
provided desktop owner through DeviceSessionManager.probe_owner_epoch before and
after consumption and checks every record against that owner/epoch and one
session/challenge. A separate supplied-record entry never grants transport
attribution. No new HMAC, Probe protocol, normalization, collector, or provenance
policy is introduced. Empty results have no evidence-derived session/challenge;
those remain missing. No history aggregation or newest-sample selection.

## E. Implementation

The implementation is located in `local-agent/src/vector_agent/reference/evidence_adapter.py`
(369 lines), with updates to `comparator.py` and `reference/__init__.py`.

### 1. Architecture and Public APIs

`DiagnosticEvidenceAdapter` encapsulates `SpecificationComparator` and `DeviceResolver`
to provide two distinct evaluation entry points:

1. `collect_and_compare(connection, operation, diagnostic_id=None, *, owner, manager) -> DiagnosticEvidenceComparison`:
   - Directly executes one authenticated lifecycle exchange via `ProbeConnection.diagnostic()`.
   - Requires an active `ProbeConnection`, an authorized `DeviceSession` owner, and the corresponding `DeviceSessionManager`.
   - Pre-exchange ownership check: verifies `connection._owner is owner` and `connection._manager is manager` prior to issuing any transport command. Rejects foreign or mismatched owners with `ValueError("Probe connection belongs to a different desktop owner.")`.
   - Pre-exchange epoch check: retrieves `manager.probe_owner_epoch(owner)` and ensures epoch is valid ($\ge 0$). Offline or invalid sessions raise `ValueError("Current authorized desktop owner required.")`.
   - Executes `connection.diagnostic(operation, diagnostic_id)`. Transport and lifecycle exceptions propagate without modification; no failed exchange is converted into a comparison verdict.
   - Post-exchange epoch verification: verifies `manager.probe_owner_epoch(owner) == epoch` immediately after the exchange and again after reference comparison. Any epoch shift during execution raises `ValueError("Desktop ownership changed...")`.
   - Terminal poll tracking: uses a `WeakKeyDictionary[ProbeConnection, tuple[int, str, str]]` protected by a threading lock to record `(epoch, probe_session_id, challenge_id)` for non-running states. A repeated poll on the same terminal challenge returns the canonical normalization unchanged, but marks it unadmitted (`attributed=False`) to prevent repeated attribution from fresh sequence counters.
   - Sets `transport_attributed=True` when all lifecycle checks pass.

2. `compare(result, *, owner) -> DiagnosticEvidenceComparison`:
   - Ingests caller-supplied canonical `DiagnosticResult`.
   - Always evaluates with `transport_attributed=False` and `ProvenanceSubjectBinding.UNBOUND`.
   - Caller-supplied results can NEVER inherit transport attribution or authenticated lifecycle standing, regardless of whether internal metadata fields match the current session.

### 2. Canonical EvidenceRecord Validation and Re-Validation (`_validated_report`)

Before any record is evaluated, `_validated_report` verifies the canonical structure:
- Validates `result.status` is a valid `DiagnosticStatus` enum and evidence list length $\le 64$.
- Each record in `result.evidence` must be an `EvidenceRecord` instance with a valid `UUID` `evidence_id`.
- Revalidates owner binding: `record.device_id == owner.device_id` and `record.diagnostic_id == result.diagnostic_id`.
- Revalidates normalization metadata into strict `_RecordContext`: validates `device_session_epoch == epoch`, consistent `probe_session_id`, `challenge_id`, `collection_elapsed_ms`, `collection_state`, `reason`, `qualification == "CODE_TESTED"`, and `authenticity == "UNKNOWN"`. Any mismatch across records raises `ValueError("Mixed or stale diagnostic context.")`.
- Enforces strict UTC timestamps via `require_utc(record.timestamp)`.
- Validates source type: `user_report` requires `EvidenceSourceType.USER_ASSISTED`; all other metrics require `EvidenceSourceType.VECTOR_PROBE`.
- Numeric measurement validation: finite float/int, bounds $|v| \le 2^{53}$, non-negative quantity checks for units `bytes`, `pixels`, `count`, `Hz`, `uAh`. Coerces exact float representations back to `int` for integer metrics.
- Re-validates against 8C's frozen `DiagnosticReport` and `DiagnosticMetric` schemas, ensuring `(report.state == "RUNNING") == (result.status == DiagnosticStatus.RUNNING)`.

### 3. Admission Rules and Property Mapping

`_compare` enforces strict admission criteria:
- **Admitted Metrics**: Only runtime capability declarations (`feature_nfc`, `feature_barometer`) are admitted, requiring:
  - `attributed == True`
  - `report.state == "COMPLETED"`
  - `report.diagnostic_id == "connectivity"`
  - `report.outcome == "INCONCLUSIVE"`
  - `report.reason == "CAPABILITY_ONLY"`
  - `record.error is None`
  - `record.normalized_value is not None`
  - `record.source_type == EvidenceSourceType.VECTOR_PROBE`
  Admitted records map strictly to `sensors.nfc_present` and `sensors.barometer_present`.
- **Incompatible Telemetry Handling**: Telemetry metrics (`charge_counter`, `ram_total`, `ram_available`, `width`, `height`, `display_width`, `display_height`, `refresh_rate`, modes) with `reason == "TELEMETRY_ONLY"` are explicitly marked `ComparisonOutcome.NOT_COMPARABLE` in the report item rather than converted to physical specifications.
- **Unavailable / Incomplete Data**: Records with `normalized_value is None` or `error is not None` produce `reason = "Measurement unavailable; missing data is not zero or hardware absence."` and remain `ComparisonOutcome.INSUFFICIENT_EVIDENCE`.
- **Unattributed Records**: Caller-supplied records produce `reason = "Supplied record has no authenticated lifecycle association."` and are not admitted.

### 4. Duplicate and Conflicting Observation Handling

- **Identical Duplicates**: Exact duplicate `EvidenceRecord` instances (matching `evidence_id` and all fields) are idempotent. They do not generate duplicate observations, increment counts, or alter provenance.
- **Conflicting Identifiers**: A duplicate record with an identical `evidence_id` but conflicting field values immediately raises `ValueError("Conflicting evidence identifier.")`.
- **Multiple Samples**: Multiple distinct observations (distinct `evidence_id`) for the same metric name raise `ValueError("Multiple observations for one metric; no sample selection policy.")`. Vector does not implement a newest-sample, average, or arbitrary tie-breaking policy; conflicting samples fail closed.
- **Order Independence**: Tests verify that swapping the order of conflicting or duplicate records produces identical rejection and fail-closed outcomes.

### 5. Defensive Copying and Information Hiding

- `DiagnosticResult` is deep-copied before evaluation; canonical records, timestamps, and IDs are never mutated.
- The returned `DiagnosticEvidenceComparison` contains:
  - `report`: `SpecificationComparisonReport`
  - `diagnostic_result`: Defensive copy of canonical result (excluded from `__repr__`)
  - `uses`: Tuple of `EvidenceUse` records tracking per-record admission decisions (`evidence_id`, `property_paths`, `admitted`, `reason`, `authority`, `binding`)
  - `transport_attributed`: Boolean indicating direct authenticated lifecycle attribution
  - `rejection`: Sanitized rejection string (does not leak private caller identifiers or raw serial numbers)
  - `qualification`: Fixed literal `"CODE_TESTED"`
  - `authenticity`: Fixed `AuthenticityLabel.UNKNOWN`
- Private test markers and raw identifiers in metadata are excluded from serialized output and `__repr__`.

All 5 scenarios execute end-to-end through `DiagnosticEvidenceAdapter.collect_and_compare`.
Key integration guarantees verified:
- Wire frames are signed with HMAC-SHA256 and authenticated by production transport.
- Corrupted wire bytes fail HMAC authentication and raise `DiagnosticSessionError`.
- Tampered framing context (`probe_session_id`, `device_epoch`, `binding`) is rejected by transport.
- Stale desktop owner or foreign manager calls are rejected prior to sending wire commands.
- Devices without discovered model identity correctly evaluate to `ResolutionStatus.UNKNOWN_DEVICE` with all comparison items `REFERENCE_UNAVAILABLE`.
- All replay transcripts yield `qualification = "CODE_TESTED"` and `authenticity = UNKNOWN`.
