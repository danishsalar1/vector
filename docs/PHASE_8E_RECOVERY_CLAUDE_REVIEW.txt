**RR-02 MEDIUM: the battery check still reaches PASS with an unknown or invalid status**
- **Cause:**
  - `bridge.py:1088` passes unrecognised status codes through as raw strings, and maps `1` to "Unknown".
  - `bridge.py:1151-1160` counts any non-empty status toward the "3 of 4 fields" PASS rule.
- **Trigger:** `level: 83`, `scale: 100`, `voltage: 4127`, `status: 1`, with no temperature line. The same happens with `status: 99` or `status: garbage`.
- **Result:** PASS, with `battery_charging_status = "Unknown"` (or `"99"`) published as evidence (`battery_diagnostic.py:270-271`). This contradicts the handoff's "a reported invalid field prevents PASS". The new test at `test_recovery_safety.py:44-57` always supplies a temperature, so it misses this case.
- **Smallest correction:**
  - Count only the recognised AOSP status codes 2–5.
  - Don't count "Unknown" (1).
  - Add unrecognised codes to `invalid_fields`.
  - Add these three cases to the test with the temperature omitted.

**RR-03 MEDIUM: the LIVE view says "No Android device detected" for a phone that is attached but offline in ADB**
- **Cause:**
  - `LiveDiagnosticProvider.ts:53-55` drops every OFFLINE session, not just leftover history.
  - `bridge.py:964-968` maps ADB `offline` and every unrecognised ADB state (such as `authorizing` or `recovery`) to OFFLINE.
  - `session.py:153-160` refreshes those sessions on every discovery cycle, so they are current devices.
- **Trigger:** `adb devices -l` prints `SERIAL offline usb:1-1`.
- **Result:**
  - The provider reports `NO_DEVICE` with count 0, and the UI shows "No Android device detected" (`AndroidStatus.tsx:147-156`).
  - The correct offline guidance at `AndroidStatus.tsx:173-183` can no longer be reached in LIVE mode.
  - `recovery_safety.test.tsx:24` pins the wrong behaviour.
  - This is a regression from before the recovery. The handoff says only "retained" OFFLINE sessions are excluded.
- **Smallest correction:**
  - If no usable Android device remains but OFFLINE entries exist, return `OFFLINE` with wording that covers "offline or disconnected".
  - The exact fix is a backend flag for "seen in the latest discovery".

**RR-04 MEDIUM: the mmWave item silently disappears when the variant is ambiguous**

- **Smallest correction:** append the consensus comparison with its consensus note, or at least append the reference item, and add a regression test.
