# Phase 8C Android diagnostic matrix

## Implementation Status
Phase 8C deep functional diagnostics candidate implemented and unit-tested in JVM/Robolectric.
Every row's qualification level is **`CODE_TESTED`**. Physical hardware qualification has **NOT RUN**
(pending physical qualification on API 26, 28, 29, 31, 33, 34 and 35 across physical OEM hardware).
No provenance assessment, component authenticity verdict, or scoring is performed or authorized.
Runtime discovery, not a model catalog or marketing string, determines availability.

### Test-layer legend (how each `CODE_TESTED` row was exercised)
- **JVM**: pure Java unit tests of the decision logic (`DiagnosticJobTest`, `DiagnosticProtocolTest`).
- **Robolectric**: the real `DiagnosticController`, collectors and UI on simulated Android API 26 and 35
  (`DiagnosticAndroidTest`). Simulated framework behaviour is not handset behaviour.
- **Contract**: the cross-language contract (`DiagnosticCrossLanguageExportTest` +
  `test_phase8c_cross_language.py`, scenarios in `local-agent/tests/fixtures/cross_language/contract.json`):
  real Android components answer the production Python session's requests; the desktop replays the
  exact bytes through the real lifecycle, HMAC transport, schemas and evidence mapping.
- **Schema**: desktop validator tests (`test_phase8c_diagnostics.py`).
- **HAL boundary (camera)**: Robolectric runs the real Camera2 open, session and `capture()` calls
  (API 35 only; its API 26 Camera2 cannot create sessions), but cannot deliver frames or capture
  results. Those enter at `CameraCollector.onFrame` / `onCaptureResult` / `onCaptureFailed`, the same
  methods the HAL callbacks call. Real HAL delivery is **NOT HARDWARE TESTED**.

## Common outcome and privacy contract

Unless a row explicitly states a predicate, there is **no functional PASS or FAIL**.
Capability and telemetry observations remain INCONCLUSIVE about hardware health.
Absent hardware/API/measurement is UNSUPPORTED; denied access is RESTRICTED (with PERMISSION_REQUIRED or PERMISSION_DENIED);
insufficient observations, interruption, busy hardware or human-only reports are
INCONCLUSIVE; unexpected execution/initialization failures are ERROR. Timeouts
and cancellation preserve partial measurements and cannot produce PASS.
Every job is session/binding owned, bounded to 60 seconds, with one active job,
one retained result, generation guards, foreground consent and cleanup on all
terminal paths. A cancellation first reports `RUNNING/INCONCLUSIVE/STOPPING` with frozen evidence,
then the terminal state only after the owned resource is released: `CANCELLED`/`EXPIRED` with
`INCONCLUSIVE/CANCELLED|TIMEOUT`, or `ERROR/CLEANUP_ERROR` when release failed. Once the 256-challenge
session budget is spent, only `START_CHALLENGE` answers `ERROR` and the desktop ends the session as
`SESSION_EXPIRED`; a stale `FETCH`/`CANCEL` answers `UNAVAILABLE`. No images, audio, coordinates,
network/device identifiers or free-form OEM strings leave the device. Human reports are explicitly
identified (`user_report`, `USER_ASSISTED`). A missing value is never zero: the desktop labels it
`NOT_YET_MEASURED`, `INTERRUPTED_BEFORE_MEASUREMENT`, `NO_SAMPLES_OBSERVED` or `UNSUPPORTED_MEASUREMENT`.
