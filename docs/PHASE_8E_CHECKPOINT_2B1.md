## 3. Before-Fix Reproductions for QG-02, QG-03 and QG-04

All three defects were reproduced on the unchanged codebase prior to code edits:

### Reproduction 1: QG-02 (AttributeError on `owner=None`)
```python
adapter = DiagnosticEvidenceAdapter(build_seed_catalog())
adapter.compare(None, owner=None)
# Raised: AttributeError: 'NoneType' object has no attribute 'session_epoch'
```
*Root cause*: `compare()` dereferenced `owner.session_epoch` at line 207 prior to calling `_compare()`, which contained the `isinstance(owner, DeviceSession)` guard.

### Reproduction 2: QG-02 (AttributeError on non-datetime timestamp)
```python
manager, owner, result = fabricated_result()
result.evidence[0].timestamp = "2026-10-09T12:00:00Z"
adapter = DiagnosticEvidenceAdapter(build_seed_catalog())
adapter.compare(result, owner=owner)
# Raised: AttributeError: 'str' object has no attribute 'tzinfo'
```
*Root cause*: `_validated_report()` called `require_utc(record.timestamp)` directly without verifying `isinstance(record.timestamp, datetime)`. `require_utc()` accessed `.tzinfo`, escaping `_compare`'s exception handler as an unhandled `AttributeError`.

### Reproduction 3: QG-03 (No-metric lifecycle response mislabeled)
```python
# Valid lifecycle exchange with empty evidence list
empty_result = DiagnosticResult.model_validate({
    "diagnostic_id": "connectivity",
    "diagnostic_name": "Connectivity Diagnostic",
    "category": "HARDWARE",
    "automation_level": "AUTOMATIC",
    "status": DiagnosticStatus.RUNNING,
    "evidence": [],
})
compared = adapter._compare(empty_result, owner=owner, epoch=owner.session_epoch, attributed=True)
# Result: honesty_disclaimer = 'Unverified supplied evidence; no authenticated Probe attribution. ...'
# Result: transport_attributed = False
```
*Root cause*: When `result.evidence` was empty, `_validated_report()` returned `None, None`. In `_compare()`, `attributed = attributed and rejection is None and report is not None` forced `attributed = False`. The disclaimer branch checked only `if attributed:`, so empty lifecycle responses defaulted to the caller-supplied wording `"Unverified supplied evidence..."`.

### Reproduction 4: QG-04 (Duplicate EvidenceUse entries)
```python
manager, owner, result = fabricated_result()  # 2 evidence records
result.evidence.append(result.evidence[0].model_copy(deep=True))  # 3 records (1 exact duplicate)
compared = unit_admission(result, owner)
# Result: len(result.evidence) == 3, len(compared.uses) == 3
# Result: compared.uses contains duplicate entries with identical evidence_id
```
*Root cause*: `_compare()` iterated over `result.evidence` and appended an `EvidenceUse` for every record without tracking seen evidence IDs. Furthermore, `comparison.items` used `zip(result.evidence, uses, strict=True)`, coupling record count strictly to `uses` length.

## 4. New QG-01 Mutation-Sensitive Regression Tests

A total of 38 regression test cases were added to `local-agent/tests/test_phase8e_checkpoint2b.py` (expanding the suite from 94 to 132 tests):

1. **Epoch change after diagnostic exchange** (`test_epoch_change_after_diagnostic_exchange_rejects_attribution`):
   Simulates desktop owner epoch increment during `connection.diagnostic()` exchange; verifies `ValueError("Desktop ownership changed during diagnostic exchange.")`.
2. **Epoch change during comparison** (`test_epoch_change_during_comparison_rejects_and_prevents_terminal_recording`):
   Simulates owner epoch increment during `_compare()`; verifies `ValueError("Desktop ownership changed during comparison.")` and confirms connection is NOT recorded in `adapter._terminal`.
3. **Diagnostic identifier mismatch** (`test_diagnostic_id_mismatch_between_record_and_result_is_rejected`):
   Sets `record.diagnostic_id = "storage"` inside a `"connectivity"` result; verifies `rejection is not None`, `transport_attributed == False`, and zero admitted uses.
4. **Invalid timestamps and timezones** (`test_invalid_timestamp_types_and_timezones_fail_predictably`, 5 parameterized cases):
   Tests string timestamp, integer unix timestamp, `None`, naive datetime, and non-UTC timezone (`+05:00`). Verifies all fail with `ValueError` and produce canonical rejection without `AttributeError`.
5. **Valid UTC timestamp accepted** (`test_valid_timezone_aware_utc_timestamp_is_accepted`):
   Tests explicit timezone-aware UTC datetime (`datetime(..., tzinfo=UTC)`); verifies valid report and admission.
6. **Input type validation in `compare()`** (`test_invalid_owner_type_in_compare_raises_type_error`, `test_invalid_result_type_in_compare_raises_type_error`, 6 cases):
   Verifies passing `None`, strings, integers, or dicts raises `TypeError("Canonical diagnostic result and desktop owner required.")`.
7. **Negative measurement quantities** (`test_negative_measurement_quantities`, 8 parameterized cases):
   Tests 5 forbidden negative quantities (`bytes_written`, `width`, `mode_count`, `refresh_rate`, `charge_counter`) and verifies rejection with `ValueError("Negative collection quantity.")`. Tests 3 valid signed sensor measurements (`axis0_mean` in `m_s2`, `axis1_mean` in `rad_s`, `axis2_mean` in `celsius`) and verifies acceptance of negative values.
8. **RUNNING vs completed state coherence** (`test_running_versus_completed_state_coherence`, 2 cases):
   Verifies `DiagnosticStatus.RUNNING` with `collection_state == "COMPLETED"` is rejected (`ValueError("Normalized status disagrees with collection state.")`), and `DiagnosticStatus.INCONCLUSIVE` with `collection_state == "RUNNING"` is rejected.
9. **EvidenceUse binding and authority** (`test_evidence_use_binding_and_authority_classification`):
   Verifies caller-supplied records have `UNBOUND` binding and `DEVICE_REPORTED_METADATA` authority. Verifies attributed records have `DEVICE_BOUND` binding. Verifies authority is never `OEM_AUTHORITATIVE`, qualification is `CODE_TESTED`, and authenticity is `UNKNOWN`.
10. **Lifecycle telemetry attribution** (`test_lifecycle_telemetry_preserves_not_comparable_conclusion`, 4 cases):
    Verifies `charge_counter`, `ram_total`, `width`, and `refresh_rate` maintain `ComparisonOutcome.NOT_COMPARABLE` even when received through the lifecycle.
11. **Legacy comparator explicit empty lists** (`test_legacy_comparator_explicit_empty_list_triggers_rejection`, 2 cases):
    Verifies `compare(..., evidence_records=[])` and `compare(..., diagnostic_results=[])` raise `ValueError("Use DiagnosticEvidenceAdapter for canonical diagnostic evidence.")`.
12. **New challenge after terminal poll** (`test_new_challenge_after_terminal_poll_receives_attribution`):
    Verifies repeated poll on same terminal challenge is unadmitted, but a subsequent exchange with a fresh `challenge_id` receives attribution (`transport_attributed == True`).
13. **Terminal deduplication locality** (`test_terminal_deduplication_is_local_to_adapter_instance`):
    Verifies that `_terminal` cache is local to each adapter instance and does not enforce cross-instance deduplication.
14. **NFC toggle hardware presence** (`test_nfc_toggle_cannot_prove_hardware_presence_even_when_completed`):
    Verifies `nfc_enabled = 1` cannot prove hardware presence and results in `INSUFFICIENT_EVIDENCE`.
15. **Zero-metric lifecycle response disclaimer** (`test_zero_metric_lifecycle_response_has_truthful_disclaimer`, 3 cases):
    Verifies valid lifecycle responses with zero metrics (`RUNNING`, `RESTRICTED`, `UNSUPPORTED`) receive `"Authenticated lifecycle exchange produced no diagnostic evidence; CODE_TESTED only."`, while caller-supplied empty results receive `"Unverified supplied evidence..."`.
16. **Duplicate EvidenceRecord idempotency & order independence** (`test_duplicate_evidence_record_produces_single_evidence_use_order_independent`):
    Verifies that appending a duplicate record produces exactly 2 `EvidenceUse` entries for 2 unique evidence IDs, preserves 3 records in `diagnostic_result`, and yields identical outcomes regardless of record order.

## 6. Evidence Ownership and Attribution After the Fixes

- **Direct Lifecycle Attribution**:
  - Requires active `ProbeConnection`, valid `DeviceSession` owner, matching manager references, and consistent pre- and post-exchange epochs.
  - Non-empty, admitted records receive `transport_attributed = True`, `ProvenanceSubjectBinding.DEVICE_BOUND`, and `DEVICE_REPORTED_METADATA` authority.
- **Empty Lifecycle Responses**:
  - Valid exchanges producing 0 metrics receive `transport_attributed = False`, 0 admitted uses, and truthful disclaimer:
    `"Authenticated lifecycle exchange produced no diagnostic evidence; CODE_TESTED only."`
  - Nonexistent evidence is never marked as admitted or authenticated measurement evidence.
- **Caller-Supplied Records**:
  - Always receive `transport_attributed = False`, `ProvenanceSubjectBinding.UNBOUND`, and disclaimer:
    `"Unverified supplied evidence; no authenticated Probe attribution."`
  - Cannot inherit transport attribution under any circumstances.
- **Non-Authority Guarantee**:
  - No input can gain `OEM_AUTHORITATIVE` authority through this adapter.
  - Authenticity remains strictly `AuthenticityLabel.UNKNOWN`.
  - Qualification remains strictly `"CODE_TESTED"`.

## 7. Duplicate and Conflicting Observation Behavior

- **Exact Duplicates**:
  - Identical `EvidenceRecord` instances (matching `evidence_id` and all attributes) are idempotent.
  - Produces at most one `EvidenceUse` entry per unique `evidence_id`.
  - Preserves original diagnostic evidence records in `diagnostic_result.evidence`.
- **Conflicting Records (Same ID, Different Values)**:
  - Fails closed immediately with `ValueError("Conflicting evidence identifier.")` in validation.
- **Multiple Samples (Different IDs, Same Metric Name)**:
  - Fails closed immediately with `ValueError("Multiple observations for one metric; no sample selection policy.")`.
  - Vector does not implement arbitrary tie-breaking (e.g. latest-wins or averaging).
- **Order Independence**:
  - Reversing record order produces identical comparison items, consistent/differs counts, and rejection status.
